# CV5-BASE readiness (grouped 5-fold cross-validation)

Date 2026-10-24. Protocol: `reports/cv5_protocol.md` (pre-registered before any CV training). **No CV result exists yet.** The local
smoke run below used 1-epoch models only to test the pipeline. Its numbers are not results and are not reported.

## 1. Is 5-fold evaluation valid for these annotations?

Yes, at the **radiograph** level.
* Every finding carries its radiograph group. Groups were built with exact (SHA-256) and near-duplicate (dHash + correlation) merging,
  and 0 near duplicates were confirmed in the pool.
* The pool has 581 radiographs and 3,010 findings: 541 `dentex_train_disease` radiographs (2,851 findings, the primary population)
  and 40 DENTEX official-validation radiographs (159 findings, secondary, never trained on).
* Each fold has 113-118 radiographs and 19-21 radiographs with a Periapical Lesion.
* **Patient-level independence cannot be claimed.** DENTEX has no patient identifiers, so two radiographs of one patient can fall in
  different folds.

* **Fold file:** `data/splits/cv5_folds_v1.csv` (SHA-256 `9b767a48…47a6`), approved by the owner on 2026-10-24 (P4 option B,

* **How it was made:** by the existing generator `scripts/dataset/make_cv_folds.py --approved-v1`, extended with an opt-in fourth

Per fold, the training side is split into fitting (377-381 radiographs) and a group-disjoint inner validation subset (53-55
radiographs). The inner subset is used for epoch selection only. Each fold predicts its 106-110 held-out primary radiographs (530-592
findings), plus 28-39 official-val findings as a secondary set.

## 3. Leakage and integrity checks

| Check | Result |
|---|---|
| Gate 1: fold file hash; every pool group once; no calibration/test group or image hash in the pool; no image in two folds | passed on the real manifests (local and in the smoke run) |
| Gate 2: fit / inner / held-out pairwise disjoint by group and image hash, per fold; fitting data = BASE source only | passed for all 5 folds |
| Gate 3: regenerated production-detector boxes vs cached boxes, 65 old-validation radiographs | passed locally: 331/331 findings same match, median box IoU 0.99995 (re-checked on Kaggle) |
| Gates 4-5: no failed run; exactly one out-of-fold prediction per primary finding per seed | passed in the smoke run (1 seed) |
| Test split | never read. The test and calibration manifests are read only for gate 1 and deleted from memory before any image work |

## 4. Tests

* `tests/test_cv5.py`: 22 tests, all passing. They cover:
  - the approved and draft fold files reproduced by the generator, and order independence;
  - refusal of any other fold file;
  - the fold gate catching a test radiograph and an image placed in two folds;
  - per-fold plans disjoint and covering each of the 2,851 primary findings exactly once;
  - the inner subset at about 1/8 and deterministic;
  - official-val findings never trained on, and the plan gate catching injected leakage;

## 5. Kaggle notebook

`kaggle/dentamind_5fold_cv.ipynb` (12 cells), generated by `kaggle/make_cv5_notebook.py`.

* **Inputs:** only the private bundle dataset already on Kaggle (`btechgd10/dentamind-ai-training-bundle`, version 3). Its library,
  split manifests, detector checkpoint and cached boxes have the same SHA-256 as the local files used here, so no new upload is
  needed. Three files not in the bundle are embedded in the notebook and hash-checked: `cv5_lib.py`, `make_cv_folds.py` and
  `cv5_folds_v1.csv`.
* **Settings:** GPU (T4) and Internet on. DENTEX images are downloaded from the official archive and verified per image.
* **Runtime estimate** (not measured for the full run): about 25 × 3 min of training, plus 10-30 min of image download, plus about 2 min
  of detector inference. That is about 1.5-2 h, well inside the 11 h budget. The notebook is resumable: per-run state, finished runs
  skipped, and `RESUME_FROM`.
* **Output:** `dentamind_5fold_cv_artifacts.zip` containing:
  - `cv5_results.json`, `oof_predictions.csv` and `caries_confusion_findings.csv`;
  - `fold_plan.json`, `detector_boxes_pool.json`, per-run `result.json` / `cv_run.json` / held-out predictions;
  - the checkpoint manifest, configs, embedded code, the fold file and SHA256SUMS.
  The 25 checkpoints (about 94 MB each) stay in the notebook output and are listed by hash.

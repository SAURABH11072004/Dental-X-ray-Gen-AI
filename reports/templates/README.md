# Templates for clinician annotation intake and source provenance

These are **templates with no entries**. They hold no real reviewer, label, count or hash. Filled-in copies belong in
`data/annotation/`, created by the project owner. They are never generated by the assistant.

## `clinician_annotation_intake_template.csv`

One row per radiograph per review batch. It tracks the work; it does **not** record labels. Labels exist only in the hash-chained review
log (`data/annotation/clinical_reviews.jsonl`), imported from the Label Studio export with `scripts/dataset/clinical_review.py`.

| Column | Meaning / rule |
|---|---|
| `intake_batch_id` | the review batch, e.g. `02` |
| `pool_id`, `image_id`, `image_sha256`, `source_dataset`, `split_lock` | copied from `data/annotation/annotation_pool.csv`. Only `split_lock = unassigned` radiographs can ever be imported under CV5. |
| `reviewer_id` | must exist in `data/annotation/reviewers.csv` with qualification and attestation filled in |
| `reviewer_qualification_attested` | `yes` only if `reviewers.csv` has `qualification`, `attested_by` and `attested_on` |
| `review_tool` | e.g. `Label Studio (data/annotation/review_config.xml)` |
| `review_started_on`, `review_completed_on` | dates |
| `regions_marked` | number of boxes the clinician drew or confirmed. Model suggestions that were not confirmed are not counted. |
| `coverage_statement` | whether all target findings on the radiograph were marked. Hanoi requires the full-coverage statement (P3). |
| `second_reader_id`, `second_reader_agreement` | only if the owner adopts a second-reader subset; otherwise leave empty |
| `export_file`, `export_file_sha256` | the Label Studio JSON export that was imported into the review log |
| `notes` | free text |

## `source_provenance_template.json`

One record per source, used by `scripts/dataset/build_cv5_import_manifest.py --provenance`.
* Every field is required.
* A blank or placeholder value makes the build refuse.
* Values come from the data holder's documentation, never from guesses.

## From intake to a P2 count (summary of `reports/data_acquisition_checklist.md`)
1. Review in Label Studio, then `clinical_review.py` import of the export (the hash chain must verify).
2. `clinical_review.export_verified`, which writes `verified_findings.csv`.
3. `expansion_report.py`, which is the binding P2 count.
4. `build_cv5_import_manifest.py`, which writes the immutable manifest and prints its SHA-256.
5. Gate V6 (`cv5_imports.gate_v6_for_manifest`) on the real images.
6. Enter the manifest SHA-256 and the counts in Amendment 02. The owner signs.

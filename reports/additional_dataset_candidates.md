# Additional dataset candidates for the four-class finding classifier

Investigated 2026-10-16. Target classes: **Caries, Deep Caries, Impacted, Periapical Lesion** (DENTEX diagnosis taxonomy,
panoramic radiographs). Machine-readable table: `reports/dataset_source_inventory.csv` (generated by `scripts/dataset/sources.py`).
Every number below was read from the source itself (Hugging Face API, archive central directory, downloaded label files, dataset
landing pages). Nothing was downloaded from an unofficial mirror, and no access control was bypassed.

## Summary

| Source | Access / licence | Usable for the four classes? | Status | Findings added to training |
|---|---|---|---|---|
| DENTEX official **validation** set (`validation_triple.json` + `validation_data.zip`) | public, CC BY-NC-SA 4.0 | **Yes**: same COCO schema, same category ids and names as the training file | downloaded, verified, **integrated (Experiment D)** | **159** (Caries 85, Deep Caries 29, Impacted 36, Periapical Lesion 9) |
| DENTEX official **test** set (`test_data.zip`) | public, CC BY-NC-SA 4.0 | **No**: labels use a different, treatment-oriented Turkish taxonomy that does not match the four diagnoses (evidence below) | downloaded, verified, inventoried, **not used** | 0 |
| Dental OPG XRAY Dataset (Mendeley `c4hhrkxytw`) | public, CC BY 4.0 | No (only "Impacted" matches; caries not split by depth; "Infection" undefined); images are phone-camera photos of films | rejected | 0 |
| Four common dental diseases (Mendeley `wxv6h9p39g`) | public, CC BY 4.0 | No (Cavities / Damage / Infection / Wisdom teeth) | rejected | 0 |
| Children's panoramic radiographs (Sci Data 2023, figshare) | public; data licence not stated in the article | No (paediatric; caries not split by depth; "periapical infection" undefined relative to DENTEX) | rejected | 0 |
| Tufts Dental Database | access request form | Unknown without access (abnormality descriptions, not the DENTEX four) | **not accessed: needs your registration** | 0 |
| OdontoAI | not verified | No diagnosis labels in the public release (teeth / FDI only) | rejected for the classifier | 0 |

**Net effect:** only one source is semantically compatible, and it is small. Deep Caries training crops rise from 438 to 467
(+6.6 %) and Periapical Lesion from 120 to 129 (+7.5 %). This data cannot materially fix a 12.9 : 1 imbalance; Experiment D
measures whether it helps at all. No new independent test set was obtained.

## 1. DENTEX official validation set (integrated)

* Name / source: DENTEX (Dental Enumeration and Diagnosis on Panoramic X-rays), Hugging Face `ibrahimhamamci/DENTEX`,
  files `DENTEX/validation_triple.json` (64,409 bytes, SHA-256 `d058afd3…f6a2`) and `DENTEX/validation_data.zip`
  (149,512,256 bytes, LFS SHA-256 `6370bb4f…7bc3`).
* Paper: Hamamci et al., *DENTEX: Dental Enumeration and Tooth Pathosis Detection Benchmark for Panoramic X-ray*,
  arXiv:2305.19112. The dataset card states that all ground truth is now available.
* Access: public, no login. Licence: CC BY-NC-SA 4.0 (non-commercial research use with attribution; derivatives share-alike).
* Image type: panoramic. Images confirmed: 50 (the 50 local files in `data/validation_data/quadrant_enumeration_disease/xrays`
  are CRC-identical to the archive members, so the local copies were used and the 150 MB zip was not re-downloaded locally).
* Annotation format: COCO JSON with `categories_1` (quadrant), `categories_2` (tooth), `categories_3` (diagnosis), boxes and
  polygons per (tooth, finding). Category ids and names are **identical** to `train_quadrant_enumeration_disease.json`
  (0 Impacted, 1 Caries, 2 Periapical Lesion, 3 Deep Caries). Mapping is still done by name, not by id.
* Counts: 182 findings on 46 images (Caries 101, Deep Caries 32, Impacted 40, Periapical Lesion 9).
* Duplicates: 20 of 50 images are byte-identical to radiographs in DENTEX's quadrant / enumeration subsets. Twins of project
  **train** images join training. Twins of project **val / calibration / test** images are **excluded** (23 findings), because adding
  their labels would change a fixed evaluation set. No image duplicates a disease-subset (classifier) radiograph; no confirmed near
  duplicates.
* Role: **training only** (default of `build_combined_manifest.py --official-val-role train`). The project's validation,
  calibration and test sets stay exactly as before, so every result remains comparable with earlier experiments.
* Limitations: small; same institutions and scanners as the training data (no new domain, so no domain-shift risk but also no
  added diversity); no patient ids.

## 2. DENTEX official test set (downloaded, not used)

* `DENTEX/test_data.zip`, 764,834,414 bytes, LFS SHA-256 `ed396d6d…82ce2` (verified after download). 250 PNG images in
  `disease/input/` and 250 Labelme JSON files in `disease/label/`. All 250 images decode.
* Labels: Labelme polygons, label string `<code>-<Turkish name>-<FDI tooth>`. Vocabulary (shapes / images):
  `0-saglam` (healthy) 91 / 3, `1-çürük` (caries) 747 / 226, `2-küretaj` (curettage) 265 / 81, `3-kanal` (root canal) 161 / 88,
  `5-çekim` (extraction) 29 / 21, `6-gömülü` (impacted) 221 / 91, `7-lezyon` (lesion) 75 / 55.
* **Why it is not mapped.** `test_181.png` is byte-identical to training image `train_332.png`, which carries English DENTEX labels.
  On that same radiograph:

  | Tooth | English (training file) | Turkish (test file) |
  |---|---|---|
  | 47, 16 | Caries | 1-çürük (agrees) |
  | 46 | Deep Caries | 7-lezyon + 5-çekim |
  | 18 | Deep Caries | 3-kanal |
  | 28 | Deep Caries | 5-çekim |
  | 45, 27 | Caries | (nothing) |
  | 26 | Caries | 3-kanal |
  | 17 | (nothing) | 7-lezyon |
  | 31, 41 | (nothing) | 2-küretaj |

  The Turkish set records treatment needs (root canal, extraction, curettage on lower incisors, a periodontal procedure) rather than
  the four diagnoses. "küretaj" is not a synonym for Deep Caries, and "lezyon" is not defined as a *periapical* lesion. Mapping them
  would force incompatible labels into the target classes. `scripts/dataset/dsutil.canonical_finding` therefore returns no class
  for this taxonomy, and `tests/test_dataset_integration.py` locks that in.
* Further finding: **95 of the 250 official test images are byte-identical to radiographs in DENTEX's training subsets**
  (mostly quadrant / enumeration). Anyone using this "test" set to evaluate the detector or the numbering model would be testing
  partly on training images.
* Only `6-gömülü → Impacted` is plausibly equivalent. Impacted is not a weak class (validation F1 about 0.93), and a test set for one
  class would not support the four-class comparison, so it was not adopted.

## 3. Rejected candidates

**Dental OPG XRAY Dataset** (Mendeley Data `c4hhrkxytw`, v4, CC BY 4.0, Rahman et al., American International University
Bangladesh). The page reports 232 originals and 604 Roboflow-augmented images with JSON labels. Classes: Healthy Teeth 223,
Caries 119, Impacted Teeth 87, Broken Down Crown/Root 52, Infection 23, Fractured Teeth 13. The images were captured with an
Android phone camera. Caries is not split into caries and deep caries, so it cannot be assigned to either DENTEX class. "Infection"
has no definition linking it to periapical lesions. There is a strong domain shift (photographs of films), and augmented copies are
mixed with originals. Not downloaded.

**Four common dental diseases** (Mendeley `wxv6h9p39g`, CC BY 4.0). The page reports 4,000 original and 10,000 augmented OPG images.
Classes: Cavities, Damage/Broken, Infection, Wisdom teeth. None is equivalent: a wisdom tooth is not necessarily impacted, and
cavities are not split by depth. Not downloaded.

**Children's dental panoramic radiographs** (Zhang et al., *Sci Data* 2023, figshare `10.6084/m9.figshare.c.6317013.v1`).
100 + 93 paediatric images (ages 2 to 13), Labelme detection labels: Caries, Periapical infection, Pulpitis, Deep sulcus,
Dental developmental abnormalities, Others. Caries is not split by depth, and "periapical infection" has no stated equivalence to
DENTEX's Periapical Lesion. Mixed dentition is a large domain shift from DENTEX (patients aged 12 and over). The article does not
state a data licence. Not downloaded.

**Tufts Dental Database** (Panetta et al., IEEE JBHI 2022; https://tdd.ece.tufts.edu/). 1,000 panoramic images with abnormality
masks and five-level text descriptions. Access is via a request form; the licence could not be read without access. **Manual step if
you want it evaluated:** request access on the site (or through the NIH Data Driven Science hub listing), accept its terms, download
it yourself, place it under `data/raw/external/tufts_dental_database/`, and tell me. Its descriptions would need a documented,
clinically reviewed mapping before any record could become one of the four classes. It must not be inferred automatically.

**OdontoAI**. Tooth segmentation with FDI numbers, but no diagnoses in the public release. A 2024 *BMC Oral Health* study
(van Nistelrooij et al.) combined OdontoAI with DENTEX and annotated diagnoses. Its data-availability statement could not be
retrieved (the publisher page blocked automated access), so no released diagnosis labels are assumed.

## 4. Data used for the Kaggle runs

* The DENTEX training disease subset is fetched on Kaggle from the official archive (`training_data.zip`, 10.9 GB). **Only** the
  `training_data/quadrant-enumeration-disease/` members (2.89 GB) are downloaded, by HTTP range requests with CRC-32 per member.
  Each image's SHA-256 must then equal the manifest value. A sample of 40 local disease images is CRC-identical to the archive.
* The official validation images are downloaded on Kaggle from `validation_data.zip` and checked against the LFS SHA-256.
* Original files are never modified. External data lives under `data/raw/external/dentex_hf/` (git-ignored), separate from the
  original DENTEX folders.

## 5. Newly verified candidates

### 5.1 Hanoi panoramic periapical-lesion dataset: ACQUIRED (labels need a clinical mapping step)
* Source: Mendeley Data `kx52tk2ddj` v3, DOI 10.17632/kx52tk2ddj.3, https://data.mendeley.com/datasets/kx52tk2ddj/3 ;
  paper: "A Dataset of apical periodontitis lesions in panoramic radiographs for deep-learning-based classification and detection",
  Data in Brief 2024 (PMC11103410).
* Licence: **CC BY 4.0** (dataset record, read from the Mendeley API). The article itself is CC BY-NC 4.0.
* Images: 3,926 original panoramic radiographs (Sirona Orthophos XG, Hanoi Medical University, 2016-2021) selected from 16,519 because
  they contain lesions; a separate folder holds 13,078 augmented copies, which are **not** used (no independent information).
* Labels: Pascal VOC XML (LabelMe), one box **around each lesion**, label = Periapical Index score 3, 4 or 5 (PAI 1-2 excluded).
  Three dentists with more than 5 years of experience, calibrated on 50 images, 2-of-3 agreement and box IoU > 0.8. No tooth number.
  Annotation archive verified: `Image Annots.rar`, SHA-256 `b263c7be…f5e` (= Mendeley), 17,004 XML (originals + augmented).
  Vocabulary over all files: PAI 3: 18,547, PAI 4: 7,597, PAI 5: 3,075 boxes.
* Why it is not mapped automatically:
  1. **Definition:** "PAI >= 3 apical periodontitis" and DENTEX "Periapical Lesion" are both periapical radiolucencies, but DENTEX
     does not publish its definition. Equivalence must be **confirmed by a dentist** (recorded in the review log), not assumed.
  2. **Geometry:** Hanoi boxes outline the lesion; the DentaMind classifier works on tooth crops. Each lesion has to be assigned to its
     tooth (box + FDI) by the reviewer, with the model's tooth box only as a suggestion.
  3. **Shortcut risk:** Hanoi contributes only positives from one scanner. If its radiographs entered training with PL labels only,
     the model could learn "Hanoi image → PL". Hanoi radiographs therefore go through **full-radiograph review** (all four classes
     marked), and results must be reported per source.
* Status: **ACQUIRED (images + expert lesion boxes); NO target label yet.** `Original JPG Images.rar` (843,554,087 bytes, SHA-256
  `e0aa741e…1111` = Mendeley) extracted: **3,924** originals (the paper says 3,926; XMLs 16091 and 16131 have no image). The image↔XML
  mapping was verified for all 3,924 (XML size = image size; all 6,741 lesion boxes inside the image: PAI 3: 4,277, PAI 4: 1,755,
  PAI 5: 709; 1.72 lesions per radiograph). **59 duplicate groups (61 redundant files)** inside the published set, so **3,863
  independent radiographs**; none duplicates a DENTEX image. Augmented images (3.6 GB) deliberately not downloaded.

### 5.2 InReDD-Dataset-PAN924: AWAITING AUTHORIZATION
* PhysioNet, DOI 10.13026/r5nt-we67; Uehara Martins et al. 2025; original paper Costa et al., OOOO 2024.
* 924 panoramic radiographs, tooth-level boxes with FDI, condition codes including **C (caries), I (impacted), M3i (impacted third
  molar)**; findings flags reportedly include periapical lesion (the published code list does not show it, so it must be checked).
  Three dentomaxillofacial radiologists (annotate, review, adjudicate).
* Access: **credentialed, restricted**. PhysioNet credentialing, signing the Contributor Review Health DUA 1.5.0, and a request to the
  authors. Licence: PhysioNet Contributor Review Health Data License 1.5.0.
* Expected use: Impacted (I/M3i) and possibly Periapical Lesion; caries has no depth, so it cannot be split into Caries / Deep Caries.
* **Your action:** create a PhysioNet account, complete credentialing, sign the DUA on the dataset page, submit the access request,
  then place the files in `data/raw/external/inredd_pan924/`.
